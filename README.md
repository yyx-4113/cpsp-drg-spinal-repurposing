# Multi-dataset target lock-in and structure-based drug repurposing for chronic postsurgical pain (CPSP)

Reproducibility package for a purely computational study of the **DRG → spinal-cord axis** in
chronic postsurgical pain: integration of public transcriptomic datasets, dual-machine-learning
hub-gene prioritisation, single-cell localisation, and **structure-based virtual screening of the
approved-drug library** with an explicit control-based validation framework.

> All numbers reported in the manuscript are generated by the scripts below; every table and figure
> is traceable to a file under `results/`. The authoritative, machine-generated summary of the P6
> screening results is [`results/P6_RESULTS.md`](results/P6_RESULTS.md).

## 4. Reproducing the virtual screen (P6)

```bash
# 0) build the approved-drug library (ChEMBL max_phase = 4) and the docking assets
python scripts/p6_fetch_assets.py        # PDB structures for the 10 dockable hub targets
python scripts/p6_ligands.py             # library + descriptors + ligand funnel
python scripts/p6_targets.py             # tractability classification (DOCK / HOLD / EXCLUDE)
python scripts/p6_receptors.py           # receptor PDBQT + box definition (crystal-ligand centred)

# 1) ONE command for the whole docking -> scoring -> figure -> report pipeline.
#    Idempotent and resumable: every step checks for its own product and skips if present;
#    docking is cached per chunk, so an interrupted run restarts only unfinished chunks.
python scripts/p6_chain.py

# 2) methodological controls (each writes its own table under results/tables/)
python scripts/p6_reverse_control.py         # ChEMBL measured-activity positive labels
python scripts/p6_mw_confounder.py           # molecular-weight confounding of enrichment
python scripts/p6_face_validity.py           # is the ranking face-valid? (reportable negative)
python scripts/p6_mw_ranking_sensitivity.py  # precision@k and rank stability under MW adjustment
python scripts/p6_throughput.py              # per-ligand cost accounting (Tier 1 vs Tier 2)
python scripts/p6_breadth.py                 # full-library breadth: composition control, rank
                                             # stability, enrichment power + MW verdict

# 3) supervised finisher (recommended). Waits until docking is idle (no vina / p6_dock process and
#    both merged tier tables are stable), then: audits and repairs stale per-tier ligand caches
#    (re-docking the affected target x tier if needed) -> re-scores, re-plots, re-reports ->
#    re-computes every methodological control that reads the ranking tables -> runs the official
#    breadth analysis -> re-audits. Fails fast: a non-zero rc in a core step aborts instead of
#    producing figures/report from a stale ranking table. Idempotent; safe to re-run. Leaves a
#    machine-readable verdict in results/tables/P6_FINALIZE_STATUS.json.
python scripts/p6_finalize_watch.py

# single-purpose audit (no writes unless --fix): does every target x tier scoring table actually
# contain exactly the ligands listed in the CURRENT tier list?
python scripts/p6_audit_liglists.py
```

> **Why the audit matters.** Docking results are cached per chunk, and a chunk filename carries
> `(target, tier, index)` but **no fingerprint of the ligand list**. If a tier list is ever
> regenerated, stale chunks are silently reused, so a target's scoring table can hold a *different*
> ligand set while still having the expected row count. Every downstream percentile then rests on a
> different ligand set for that target. `p6_audit_liglists.py` compares each `scores_<tier>.csv`
> against the current list and quarantines stale caches (via rename, never delete) so they are
> re-docked.

Artifact name map (what each script writes) is listed in §10 of the companion skill referenced at
the end of this file, and in `results/P6_RESULTS.md`.

## 5. Reproducibility conventions

- **Fixed seeds.** Vina is called with `--seed 42`; every stochastic estimator (LASSO/RF/XGBoost,
  KMeans, bootstrap, permutation tests) uses a documented fixed seed.
- **Chunk-level caching.** Docking results are written per ligand chunk. Re-running any step never
  recomputes completed work, so the pipeline survives interruptions without silent loss of effort.
- **Product-existence gating.** Each stage advances only when its real product file exists; a stage
  that produced a partial or missing product halts the pipeline instead of contaminating downstream
  scoring (see `PROJECT_PLAN.md` §4 for the statistical ground rules).
- **Cache invalidation is audited, not assumed.** Because chunk caching is keyed on
  `(target, tier, index)` rather than on the ligand list, `p6_audit_liglists.py` verifies — before
  scoring — that each `scores_<tier>.csv` contains *exactly* the ligand set of the current tier list,
  and quarantines stale caches for re-docking if not.
- **Single label definition per test.** Enrichment tests use ChEMBL *binding-type* labels
  (pChEMBL ≥ 6) only; indication/annotation-type labels are used for a separate face-validity
  analysis. No test mixes the two.
- **Confounder controls are mandatory, not optional.** Every enrichment claim is reported together
  with (i) a size-only baseline and (ii) a molecular-weight-adjusted value.
- **Audit columns.** Docking tables carry the actual `exh` / `max_evals` / wall-clock values used, so
  a table can never be detached from the parameters that produced it.

## 6. Caveats carried with every conclusion

1. **Docking is a prioritisation tool, not a binding free energy.** With the low-budget setting used
   here, rank fidelity has a measured ceiling (Spearman ρ ≈ 0.78 against the gold standard); results
   are framed as *candidate prioritisation*, not precise ordering.
2. **Single crystal conformations** — no induced fit, no membrane environment, no explicit waters.
3. **Cross-target raw scores are not comparable.** Vina scores have no common scale across pockets.
   Target prioritisation therefore uses within-target percentiles combined with druggability priors,
   never raw kcal/mol. (A pocket-volume confound test is reported explicitly as a negative result.)
4. **Ligand-level and single-cell pseudoreplication are avoided by construction**: drug-level
   aggregation for enrichment, sample-level tests for single-cell composition and expression.
5. **Human direct validation is absent** in the public data used here; human confirmation must come
   from prospective clinical samples.
6. All candidates remain **hypotheses** until wet-lab validation.
